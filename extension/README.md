# local music · B站收藏（浏览器插件）

逛 B 站时一键把音乐视频收藏到 local music，不用复制粘贴链接。支持多P合集整辑收藏。

**并且不需要先启动 local music**：收藏会自己找地方落脚 —— 绑定了项目目录就写进项目里，
没绑定（或目录授权过期）就先排在插件自己的队列里，local music 一启动就自动入库，一条都不会丢。

## 收藏去哪了（四级落点，插件自动选）

| 情况 | 收藏去哪 | 弹窗显示 |
|------|----------|----------|
| local music 正在运行 | 直接调本地接口，立刻进曲库（还能顺手下载、补封面） | `已连接` |
| 没运行，但已绑定项目目录且授权有效 | 插件自己抓 B 站信息，写进项目目录的 `data/extension-inbox.jsonl`，**下次启动时自动导入** | `离线模式` |
| 没运行，目录授权被浏览器收回了 | 先排进插件队列，服务一起来就自动回放入库 | `需重新授权` |
| 没运行，也没绑定目录 | 排进插件队列，服务一起来就自动回放入库（**不会丢**） | `未启动` |

队列里的收藏每分钟自动尝试回放一次，也会在你打开弹窗、逛 B 站页面、或点收藏时顺手重试；
回放走的是正常收藏接口，后端按链接去重，重复回放安全。

## 安装

**第 0 步：先把插件文件夹弄到硬盘**，两种来源挑一种：

- **下载 Release 里的 zip（推荐，只想要插件的话最省事）**
  到 [Releases](https://github.com/kekecsy/my-music/releases/latest) 下载
  `local-music-extension-v*.zip`，**解压**到任意位置（比如 `~/Downloads/local-music-extension`）。
- **用仓库里的本目录**
  `git clone https://github.com/kekecsy/my-music.git` 后直接用 `extension/` 文件夹。

> ⚠️ 必须**解压**，不能把 zip 直接拖给浏览器。也没有 `.crx` 双击安装这条路 ——
> Chrome 137 起会拦截非商店来源的 crx 侧载。只能走下面的「加载已解压的扩展程序」。

然后：

1. 打开浏览器的扩展管理页：地址栏输入 `chrome://extensions`（Edge 是 `edge://extensions`）
2. 打开右上角的「**开发者模式**」开关
3. 点击左上角「**加载已解压的扩展程序**」，选择**含 `manifest.json` 的那一层文件夹**
   （Release zip 解压后是 `local-music-extension/`；仓库方式就是 `extension/`）
4. 工具栏出现蓝紫色方块图标（戴耳机的猫）即安装成功（建议点📌固定到工具栏）

> 选错层级会提示「清单文件缺失或不可读」，说明你选中了它的上一层或下一层。
> Firefox 暂不支持（清单格式不同）。Safari 不支持。

## 绑定本地项目目录（可选，推荐）

弹窗 →「本地项目目录」→ **绑定本地项目目录**，会打开设置页：

1. 点「选择 local music 项目文件夹」
2. 选中**项目根目录**（含 `app.py`、`static/` 的那个文件夹）：
   - macOS 例：`~/Desktop/my-music`
   - Windows 例：`D:\my-music`（资源管理器里选中该文件夹即可）

   如果你用的是打包版，选**数据目录**（含 `music.db`）：
   - macOS：`~/Library/Application Support/localmusic`
   - Windows：`%APPDATA%\localmusic`（在资源管理器地址栏粘贴这一串可直接跳过去）
3. 浏览器问是否允许读写时，选「**每次访问时都允许**」
4. 如果项目放在**桌面**上，macOS 还会问一次「是否允许访问桌面上的文件」，也要点允许
   （Windows 没有这一步）

绑定后：

- 不启动 local music 也能在 B 站随手收藏，收藏会写进项目目录等你启动
- 弹窗里能看到「待同步 N 条」
- 下次启动 local music，或在曲库页面刷新一次，这些收藏会自动导入（前端会提示「已从浏览器插件同步 N 首收藏」）
- 重复收藏不会产生重复条目

### 为什么有时会提示「需要重新授权」

这是浏览器的规定，不是插件出了故障：**文件系统授权不跨会话保留**。
目录句柄能存在 IndexedDB 里（所以插件永远记得你选了哪个文件夹），但同一个来源的所有页面
都关掉之后，浏览器就收回访问权 —— 下次打开时 `queryPermission()` 只会返回 `"prompt"`，
此时**连列目录都会失败**。

所以：

- 把绑定页关掉后，弹窗显示 `需重新授权` 是**正常**现象，不是"绑定丢了"
- 在设置页点一下「**恢复读写权限**」→ 在提示里选「**每次访问时都允许**」，之后长期有效，不用重选文件夹
- 就算一直没恢复授权也不影响收藏：会先排在插件队列里，服务一启动自动入库

> 注意：**播放和下载音乐仍然需要启动 local music**（音频流由本地服务提供），
> 离线收藏只是让你"收藏"这个动作不再依赖服务。

## 使用方式

| 方式 | 操作 | 说明 |
|------|------|------|
| 悬浮按钮 | 视频页右下角的粉色心形按钮 | 单P点击直接收藏；多P会弹出面板让你选「仅这一集」或「整个合集」。按钮可以**按住拖动**换位置，会记住 |
| 工具栏弹窗 | 点扩展图标 | 显示连接状态、当前视频收藏按钮、绑定目录、右键菜单默认模式、服务地址等设置 |
| 右键菜单 | 在视频页 / 链接上右键 →「收藏到 local music」 | 按「默认模式」直接收藏（弹窗里可改成：自动 / 只收单集 / 收整个合集） |

已在曲库中（或已排队）的视频，悬浮按钮会亮**绿点**；重复收藏不会产生重复条目，会提示「曲库里已经有了」。

## 服务没在运行？

- 想直接入库、下载音频：先启动 local music（`./start.sh` / `start.bat`）
- 只想收藏：绑定项目目录后可以直接用，收藏会排队等下次启动

## 常见问题

- **服务换了端口**：在弹窗的「服务地址」里改成 `http://127.0.0.1:端口号` 即可。
- **不想看到悬浮按钮**：弹窗里关掉「视频页显示悬浮按钮」，只用工具栏弹窗和右键菜单。
- **更新插件**：改完代码后在 `chrome://extensions` 里点该插件的「重新加载」，B站页面也要刷新一次。
- **插件能看我的曲库吗**：接口只对本机与浏览器扩展开放 CORS，外部网站的请求会被拒绝；目录访问也由浏览器逐次授权，所有数据都在你自己的电脑上。

## 文件结构

```
extension/
├── manifest.json      # MV3 清单
├── background.js      # 后台：请求代理、双通道收藏、右键菜单、角标反馈
├── content.js         # B站页面：悬浮按钮、合集选择面板、toast（Shadow DOM）
├── fsaccess.js        # 项目目录绑定与读写（File System Access API，SW 与页面共用）
├── setup.html/js      # 绑定目录的设置页（独立标签页，避免 popup 被系统对话框关掉）
├── popup.html/js/css  # 工具栏弹窗
├── icons/             # 扩展图标 icon16/32/48/128.png + 源图 cover.png
└── make_icons.py      # 图标生成：从 icons/cover.png 裁剪重制（需要 pillow、numpy）
```

> 最后两行（`icons/cover.png`、`make_icons.py`）是**开发用素材**，不会打进
> Release 的 `local-music-extension-v*.zip` 里 —— 那个 zip 只含运行期必需的文件，
> 解压后的顶层目录就叫 `local-music-extension/`，直接拿去「加载已解压的扩展程序」。

图标由 `icons/cover.png`（1254×1254，四周带黑边）经 `make_icons.py` 处理而来：
自动裁掉黑边、把圆角外的黑色抠成透明（避免缩小时在边缘混出黑边）、
给 16/32 做轻度锐化。改了源图后重跑 `python3 make_icons.py` 即可。

插件写出的 `data/extension-inbox.jsonl`（每行一条 JSON）由后端在启动时导入，
导入后归档到 `data/inbox/imported-时间戳.jsonl`，可随时查看或删掉。
